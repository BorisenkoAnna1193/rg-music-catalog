RG MUSIC CATALOG - принятые решения (формат STAR для рассказа о проекте)
Каталог музыки гимнасток-художниц из английской Википедии. Статус на 01.10.2026.

==========================================================================
STEP 1. Выгрузить сырые данные о музыке из Википедии
==========================================================================

substep: Вежливый доступ к источнику
action:  Клиент MediaWiki API: User-Agent с контактом, 1 запрос/сек, maxlag, ретраи с Retry-After,
         редиректы, сохранение revid, дисковый кэш HTML.
result:  Повторный запуск не нагружает Википедию; каждая строка данных привязана к версии статьи.
tech:    Python, requests, MediaWiki Action API
file_names: rg_music/wiki_client.py (+ data/raw/ - кэш, не в git)

substep: Найти и «выпрямить» таблицы с музыкой
action:  Таблицы правятся вручную, поэтому макет плавает (rowspan, год отдельной строкой, <br>).
         Развернул таблицу в прямоугольную сетку, затем сопоставил колонки по тексту заголовков.
         Любая эвристика помечается в notes, молча ничего не исправляется.
result:  391 строка выступлений с 10 страниц, все страницы разобраны.
tech:    BeautifulSoup4, lxml, регулярные выражения
file_names: rg_music/tables.py, rg_music/extract.py -> data/interim/routines_raw.csv, competitions_raw.csv,
            extract_report.json

substep: Ошибки дат в источнике (Токио-2020)
action:  Решение с владелицей: один год = год проведения события; неверные даты исправляются с пометкой,
         а не моделируются вторым полем.
result:  Tokyo 2020 -> 2021, исправленные строки помечены year_corrected_2020_to_2021.
tech:    Python
file_names: rg_music/events.py

substep: Перекрёстная проверка двух таблиц на одной странице
action:  Сравнил музыку в таблице соревнований и в таблице выступлений (нечёткое сравнение строк).
result:  52 олимпийских выступления: 46 совпали, 5 с расхождением в год (Токио), 1 - в деталях.
tech:    difflib (SequenceMatcher), unicodedata
file_names: rg_music/crosscheck.py -> data/interim/crosscheck.csv

STEP 2. Разобрать текстовую ячейку с музыкой на структурные поля
==========================================================================

substep: Выбор подхода к разбору
action:  Сначала правила (регулярные выражения) и отчёт о покрытии, LLM - только запасной вариант
         для того, что правила не берут. Спорное не угадываем, а помечаем флагом.
result:  LLM пока не понадобился: после правил не осталось неразобранных строк.
tech:    Python re, dataclasses, pytest
file_names: rg_music/music_parser.py, rg_music/parse.py

substep: Одна ячейка - несколько треков
action:  Правила: "A by X and B by Y" режутся по разделителю между двумя "by"; "A / B / C by X / Y / Z"
         разбираются попарно по позиции; ремикс - "Poeta (remix by B)", автор - исходный артист.
         Все треки одной ячейки сохраняют один routine_id.
result:  391 выступление -> 403 трека: 382 ok, 20 partial (в источнике нет автора), 1 ссылка на другую запись.
tech:    регулярные выражения с маскировкой кавычек, pytest (50+ тестов на реальные форматы ячеек)
file_names: rg_music/music_parser.py -> data/interim/tracks.csv, parse_report.json

substep: Модель полей (решения с владелицей)
action:  Композитор и исполнитель слиты в artist (композитор первым, через запятую); отдельный performer
         только при явном "performed/conducted by". Колонка excerpt убрана (правилами не заполнить).
result:  Простая схема; различие «композитор / исполнитель» отложено до этапа сопоставления сущностей.
tech:    -
file_names: CLAUDE.md (раздел Decisions for step 2)

substep: Нормализация названий предметов
action:  ~40 написаний ("Hoop (2nd)", "Ribbons", "Gala at EC Minsk") -> apparatus + variant + context;
         опечатка "Autum" исправляется с пометкой.
result:  Все 391 значение распознаны, неизвестных нет.
tech:    Python re
file_names: rg_music/apparatus.py -> data/interim/routines_parsed.csv

substep: Слои данных
action:  raw (не меняется) -> parsed -> reviewed (ручная проверка) -> SQLite только из проверенного слоя.
         Ручные правки хранятся отдельно от результата парсера, чтобы перезапуск их не затирал.
result:  Решение принято; реализация - после проверки.
tech:    CSV на ранних слоях, SQLite позже
file_names: CLAUDE.md

STEP 3. Собрать список гимнасток (кого скачивать дальше)
==========================================================================

substep: Определение источника списка
action:  Взял страницы всех чемпионатов мира (42 шт., 1963-2026) со страницы-индекса; на каждой берутся
         таблицы индивидуальной квалификации (если есть) и финала многоборья.
         Другие источники: у FIG нет открытого списка музыки; rgforum.no (база музыки) - сайт недоступен,
         есть снимок в Wayback до 2022, отложен как второй источник.
result:  2635 появлений -> 1414 гимнасток, у 533 есть своя статья в Википедии.
tech:    Python, BeautifulSoup4, MediaWiki API
file_names: rg_music/worlds.py -> data/interim/wc_appearances.csv, wc_gymnasts.csv, wc_report.json

substep: Идентификация одного человека
action:  Ключ = ссылка на статью, приведённая через редиректы к pageid (так "Yevgenia" и "Evgenia" одного
         человека сходятся автоматически). Строки без ссылки присоединяются к статье только при точном
         совпадении ключа имени и страны и если кандидат один.
result:  19 безссылочных строк присоединены автоматически; неоднозначные оставлены на ручную проверку.
tech:    MediaWiki API (action=query, redirects), нормализация имён
file_names: rg_music/worlds.py, rg_music/wiki_client.py (resolve_titles)

substep: Обнаружение похожих написаний
action:  Ключ имени, устойчивый к транслитерации (ya/ia, ye/e, kh/h, порядок слов, диакритика);
         похожие пары ищутся нечётким сравнением (порог 0.9) внутри блоков по префиксам слов.
         Два типа строк: spelling_variants (одна статья, разные написания: translit_only / different_name)
         и possible_duplicate (похожие имена на разных статьях).
result:  Лист проверки: около 120 строк. Нашлись настоящие опечатки в Википедии: Moja/Mojca Rode,
         Hiroko Oisuka/Otsuka, Matilde Tamgnini/Tamagnini.
tech:    difflib, unicodedata, блокирование пар (blocking) для скорости
file_names: rg_music/worlds.py -> data/interim/wc_name_review.csv (колонки decision / canonical_name - за владелицей)

substep: Смена страны и фамилии
action:  Страна - часть ключа безссылочных строк; смена страны (СССР -> Россия) не склеивается автоматически,
         а попадает в лист проверки как возможный дубль. Смена фамилии (девичья/по мужу) видна как
         different_name при той же статье.
result:  Пример: Djamila Rakhmatova (таблицы) = Djamila Akhmedova (FIG) - один человек, разные фамилии.
tech:    -
file_names: data/interim/wc_name_review.csv

substep: Справочник стран (решение владелицы)
action:  Страны в таблицах записаны по-разному ("the Soviet Union", "Venezuela (1930-2006)", "KAZ", "Georgia (country)").
         Вместо ручного словаря построен справочник на ISO 3166-1 (249 действующих стран) и ISO 3166-3 (31 бывшая:
         СССР, Чехословакия, ГДР, Югославия...) + алиасы (в т.ч. коды МОК и несколько спортивных названий).
         Каждое написание из таблицы привязывается к справочнику каскадом: код -> точное совпадение -> известное
         название внутри текста -> максимально похожее (difflib, порог 0.84) -> не найдено. Метод и оценка сохраняются,
         всё неточное идёт на проверку. Годы существования страны не проверяются ("Czech Republic" в 1971 = Czech Republic).
result:  Все 134 написания привязаны (108 точно, 25 по коду, 1 по вхождению: "Chinese Taipei for Olympic Games"),
         неопознанных нет. Побочный эффект: "West Germany" = Germany, три пары-дубликата склеились сами.
         Нестрановые записи (Individual Neutral Athletes) не выбираются как "последняя страна".
tech:    Python, pycountry (ISO 3166-1/-3), difflib (нечёткое сравнение), CSV-справочники, pytest
file_names: rg_music/countries.py -> data/reference/countries.csv, data/reference/country_aliases.csv,
            data/interim/wc_country_mapping.csv (какое написание к какой стране привязалось и как)

STEP 4. Каноническое имя из официального источника (FIG)
==========================================================================

substep: Выбор источника канонических имён
action:  Идея владелицы: брать имя с сайта FIG. Проверил: открытого списка нет, зато в Викиданных у статей
         есть идентификаторы FIG (P2696, P7440), а имя лежит в HTML профиля ("AVERINA Dina").

result:  Имя FIG найдено для 62 из 123 гимнасток листа (65 строк по ссылке на статью, 3 поиском по имени,
         15 - в Викиданных нет FIG id, 41 не найдено - в основном без статьи и из старых лет).

file_names: rg_music/fig_names.py -> data/interim/wc_name_review_fig.csv, data/raw/fig_cache.json

substep: Иерархия источников для канонического имени (решение владелицы)
action:  1) имя FIG, фамилия приводится к виду "Aaaa" (AVERINA -> Averina), порядок "Имя Фамилия";
         2) если гимнастки нет в FIG, но есть статья в Википедии - заголовок статьи;
         3) если нет ни того, ни другого - написание из таблицы, которое встречается чаще (при равенстве - более позднее).
         Для пар-дубликатов: "один человек" при совпавших именах FIG, при одинаковом имени (с точностью до порядка
         слов/транслитерации) или при одной стране и отсутствии в одной таблице; "разные люди" при разных именах FIG,
         при появлении в одной таблице либо при разных стране и написании.
         Гимнастка, выступавшая за две страны (в основном правопреемники: ФРГ -> Германия, Чехословакия -> Чехия),
         получает страну последнего чемпионата.
         Ручные решения владелицы не перезаписываются: строки, заполненные скриптом, содержат причину в decision_basis.
result:  Лист проверки (117 строк): имя из FIG - 65, из Википедии - 20, из таблицы - 32. Из 17 пар-дубликатов
         15 признаны одним человеком (часть по совпавшим именам FIG или одинаковому имени в двух странах;
         9 - одна страна и не в одной таблице, имя выбрано по таблице и подтверждено владелицей)
         и 2 пары - разные люди (Natalia/Natalie Garcia, Viktoria Bogdanova/Danova).
         1410 строк гимнасток -> 1395 человек; у слитых страна = последняя.
tech:    Python (union-find для слияния, чистые функции + pytest), CSV
file_names: rg_music/name_decisions.py -> data/interim/wc_name_review_fig.csv (decision, canonical_name, decision_basis),
            data/interim/wc_gymnasts_final.csv (итоговый список людей)

substep: Кодировка файлов для Excel
action:  В Excel имя "Jovanović" отображалось как "JovanoviƒЗ". Проверка показала, что в данных ошибки нет:

STEP 6. Слить два источника музыки и сделать каталог двуязычным
==========================================================================

substep: Сезоны вместо года (решение владелицы)
action:  "2022/2023" в гимнастике означает, что музыка использовалась в оба сезона. Строка разворачивается
         в по одной строке на год, различающихся только годом (id ...#2022, ...#2023), исходный текст сохраняется.
result:  45 строк у 10 гимнасток -> 95 строк-годов (всего +50 строк).
tech:    Python, регулярные выражения
file_names: rg_music/years.py, rg_music/merge.py -> data/interim/routines_merged.csv

substep: Слияние таблицы выступлений и таблицы соревнований
action:  Правила: то же выступление = та же гимнастка + предмет + год (±1) + похожая музыка (весь текст, название
         трека/произведения либо одно название целиком внутри другого). Совпало -> соревнование записывается как
         событие выступления (у выступления их может быть несколько); не совпало -> новое выступление (у гимнасток,
         у которых есть только таблица соревнований, например Кабаева); другая музыка в тот же год -> отдельная
         строка с флагом, а не перезапись. Строки без музыки или без единого предмета (многоборье) пропускаются.
result:  +64 новых выступления из таблиц соревнований, 165 строк слиты как события, 4 настоящих конфликта между
         таблицами (например, Витриченко 2000). Итого 3964 выступления, 4072 трека, 229 событий.
         Название соревнования нужно для плашки "выступала на чемпионате мира".
tech:    Python, difflib (нечёткое сравнение), pytest
file_names: rg_music/merge.py -> data/interim/routines_merged.csv, routine_events.csv, merge_report.json

substep: Русский язык: предметы, страны, имена гимнасток
action:  Предметы - небольшой справочник (7 значений). Страны - ISO-переводы (pycountry) + короткие названия вместо
         официальных ("Россия", а не "Российская Федерация"). Имена гимнасток - из Викиданных (русская метка или
         название статьи в ru-Википедии, только кириллица), приведены к виду "Имя Фамилия" без отчества; без
         транслитерации: если русского имени нет, показывается латинское. Классические произведения и композиторы
         отложены: автоматический поиск в Викиданных путает "Spartacus" (насекомое), "Don Quixote" (роман).
result:  Все 95 используемых стран и 7 предметов переведены; русское имя есть у 163 из 533 гимнасток со статьёй
         (30%; у России/СССР/Беларуси/Украины/Болгарии 70-95%); 12 имён помечены на ручную проверку.
         Ошибка, найденная проверкой: окончание "-евич" в фамилии (Наркевич) принималось за отчество.
tech:    Python, Wikidata API (wbgetentities), pycountry (gettext-переводы ISO), pytest
file_names: rg_music/names_ru.py -> data/interim/gymnast_names_ru.csv; rg_music/apparatus.py -> data/reference/apparatus.csv;
            rg_music/countries.py -> data/reference/countries.csv (колонка name_ru)

substep: Ключ "той же музыки" (решение владелицы)
action:  Та же музыка = то же произведение (разные части одного балета - нормально); ключ = название + композитор/автор,
         а не название само по себе (разные песни бывают с одним названием).
result:  Решение зафиксировано в схеме БД (таблица work). Реализация - на шаге сопоставления музыки.
tech:    -
file_names: CLAUDE.md, docs/db_schema.md

STEP 10. Признак "классика" для фильтра и динамики по годам
==========================================================================

substep: Как отличить классику от остальной музыки
action:  Запрос владелицы: поле is_classical (1/0) у произведения, чтобы отдельно оценивать популярность классики и современной
         музыки и смотреть долю классики по годам. Признак привязан к композитору произведения, а не к исполнителю: "Болеро" остаётся
         классикой в рок-обработке, песня Michael Jackson остаётся поп-музыкой в версии для виолончелей. Порядок доказательств:
         решение владелицы (файл) -> композитор из списка классиков (89 имён) -> композитор в начале названия -> сильный признак
         в названии (опус, симфония, фортепианный концерт, соната, реквием, акт) -> 0. Основание хранится рядом (classical_basis).
         Итерации по проверке: слабые слова в названии (Rhapsody, Concerto, Nocturne, Prelude) давали ложные срабатывания
         ("Bohemian Rhapsody", "Concerto de Berlin") и были убраны; оркестр, названный по композитору ("Johann Strauss Orchestra"),
         принимался за композитора - добавлено исключение; имя без фамилии ("Adam") композитором не считается.
result:  176 из 2406 произведений - классика (140 по композитору, 14 по композитору в названии, 22 по названию). Доля выступлений
         с классикой: 31% (1990-94), 13% (2015-19), 8% (2020-24), 4% (с 2025) - тренд на уход от классики.
         Границы подтверждены владелицей: не классика - Пьяццолла/танго, Лекуона, Эйнауди, киномузыка, фольклор; классика - Гершвин,
         оперетта, рок-аранжировки классических пьес. Идея на будущее: расширить признак до жанров (классика/фолк/кино/поп/рок).
tech:    Python, CSV-справочник композиторов, правила с приоритетами и основанием, pytest
file_names: rg_music/classical.py, data/manual/classical_composers.csv, data/manual/classical_overrides.csv -> data/interim/works.csv
